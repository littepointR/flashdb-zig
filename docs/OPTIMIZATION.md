# 优化与设计取舍记录

本文记录每一项与 C 原版不同的设计，以及它为什么值得做、带来了多少收益。
Flash 计数是确定性的（与编译器优化级别无关），耗时数据见 [`BENCHMARKS.md`](BENCHMARKS.md)。

## 1. 盘面格式：把"原子性"从状态表变成单粒度提交

C 的每条 KV 记录带 5 个状态粒度（`PRE_WRITE / WRITE / PRE_DELETE / DELETED / ERR_HDR`），
TS 索引带 5 个；本实现把状态压缩为：

| 库 | 每条记录状态粒度 | 语义 |
|---|---|---|
| KVDB | 3（commit / pending / deleted） | commit 置 0 = 提交；pending = 待删除可恢复；deleted = 彻底删除 |
| TSDB | 4（commit / user1 / deleted / user2） | 与 C 的状态序一致，但少一次 PRE_WRITE 写入 |

效果（wg=8，每记录固定开销）：

| | KV 记录头 | TS 索引 |
|---|---|---|
| C 2.2.99 | 22 B | 17 B |
| 本实现 | **10 B** | **12 B** |

配套的扇区头：KV 从 18 B 降到 **10 B**（不再落盘 `using/full/dirty/gc`，挂载时扫描推导），
TS 从 41 B 降到 **24 B**（只保留 `using/full`，尾部时间信息由 `full` 粒度提交）。

## 2. 写入路径：更少的写操作

更新一个已存在键的全部闪光操作：

| 步骤 | C | 本实现 |
|---|---|---|
| 记录旧值 | 先查缓存/扫描 | 先分配空间，再查（GC 可能移动旧记录） |
| 旧值标记 | PRE_DELETE 状态写 | pending 粒度写 |
| 新记录 | PRE_WRITE 状态 + 头 + 名字 + 值 + WRITE 状态（5 次） | 头+名字（1 次）+ 值（1 次）+ commit（1 次） |
| 旧值完成 | DELETED 状态写 + 脏扇区状态读/写 | deleted 粒度写 |
| **合计** | **8–9 次写** | **4 次写** |

新建记录 5 次 → **3 次**；删除 2 次 → **1 次**（单粒度 `deleted` 写本身原子）。

## 3. 读取路径：只读必要的数据

* **查找**只读记录头（10 B）：C 的 `read_kv()` 对每条途经记录都读完整 value 并算 CRC32。
  键名长度匹配后才读名字（C 总是读满 64 B 名字缓冲）。
* **取值**一次完成"读取 + CRC32 校验 + 拷贝"：C 在查找阶段读一遍 value 算 CRC，
  `get_kv` 再读一遍拷贝。本实现 `get` 命中缓存时只需 3 次读（头 + 名字 + 值）。
* **遍历**用记录头里的长度直接算出下一条地址；C 要在后续字节里逐字节扫描魔术字。
* **缓存命中**的哈希用 16 位 tag + 分区内偏移（4 B/项）；C 是 64 项线性扫描，
  每命中一次还要从 Flash 读 64 B 名字。

实测（wg=8，宿主基准，Flash 计数确定性）：

| 场景 | C 读次数 / 读字节 | 本实现 | 比值 |
|---|---|---|---|
| kv_get_hot (2000 次) | 12000 / 330740 | 6000 / 93370 | 0.50× / 0.28× |
| kv_get_miss (500 次) | 79500 / 1606000 | 16000 / 160000 | 0.20× / 0.10× |
| kv_delete (192 次) | 38571 / 780822 | 9576 / 86700 | 0.25× / 0.11× |
| kv_iterate (100 轮) | 15900 / 321200 | 6400 / 47000 | 0.40× / 0.15× |
| kv_mount (100 次) | 23300 / 553200 | 3800 / 40200 | 0.16× / 0.07× |

## 4. RAM

| 项 | C 2.2.99 | 本实现 |
|---|---|---|
| KVDB 结构体 | 152 B | ~56 B |
| 名称缓存 | 64 × 8 B = 512 B | 128 × 4 B = 512 B（4 路组相联，可配 0/32/64/128） |
| 扇区缓存表 | 8 × 40 B = 320 B | **无**（每扇区只存 2 B 空闲偏移 + 位图） |
| `cur_kv` 临时记录 | 92 B | **无** |
| TSDB 结构体 | 160 B | ~56 B（含驱动） |

KVDB+C 合计 1064 B → 本实现约 584 B（含驱动值），且缓存命中率更高（4 路 + 雪崩哈希）。

## 5. GC

* **保留一个空扇区**给 GC：只剩 1 个可回收扇区且存在脏扇区时先搬移再分配，
  避免"无处可搬"的容量死锁（与 C 的 `FDB_GC_EMPTY_SEC_THRESHOLD` 等价，但规则更简单：
  没有脏数据时允许用掉最后一个空闲扇区，容量利用率略高于 C）。
* **只搬移可见记录**：pending/deleted/未提交记录原地丢弃。
* **崩溃安全**：搬移同样走 pending → 副本提交 → deleted；不需要"GC 进行中"标记。
* **懒认领**：空白挂载只格式化第一个扇区，其余保持整块擦除状态，认领时只需写扇区头——
  总擦除次数与 C 相同（C 在初始化时一次性擦 4 个扇区），但把擦除推迟到真正需要时。
* GC 中断的扇区天然含 pending/deleted，挂载扫描时重新标记为脏，下一轮继续回收。

## 6. ROM

* 库不引用 `std.fmt` / `std.io` / 分配器；仅用 `@memcpy`、整数运算和自写的
  小端编解码（`format.rd16/wr32` 等），避免格式化代码进固件。
* 布局/偏移/状态编码全部 `comptime` 折叠，没有运行期几何计算和查表。
* 错误用 Zig `error` 联合，没有错误码表、没有 `FDB_ASSERT` 死循环、没有日志字符串。
* CRC32 表在 `comptime` 生成（1 KiB `.rodata`，与 C 的静态表相同，可选半字节表）。

Cortex-M3 实测（同工作负载、同测量脚手架）：见 [`BENCHMARKS.md`](BENCHMARKS.md)。

## 7. 有意不做的事

* **不提供 C ABI 兼容层**：用户确认只需纯 Zig API，C 工程迁移按 README 的说明重写调用点。
* **不保持盘面字节兼容**：用户确认允许重新设计格式；作为补偿，新增了 C↔Zig
  **行为级**差分对拍（`bench/diff/`，2000 条操作逐行一致 + 掉电语义校验）。
* **不移植文件模式**与大端格式：目标平台是裸 Flash 小端 MCU；宿主测试用 `sim.RamFlash`。
* **不做运行期几何配置**：扇区大小/数量是 `comptime` 参数，换来零开销与更小的 RAM；
  需要多种几何时分别实例化类型即可。
