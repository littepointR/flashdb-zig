# 基准与验收数据

本文件比较 **Zig 重写版** 与 **C 原版 FlashDB 2.2.99** 在完全相同工作负载、相同 Flash 几何、
相同测量脚手架下的表现。原始数据由 `bench/`（宿主）与 `firmware/`（Cortex-M3/QEMU）生成，
`tools/report_tables.py` 从 JSON 自动生成下表；所有命令见文末。

## 1. 方法

* **Flash 模型**：RAM 空 NOR 模拟器（32 KiB 设备、4 KiB 擦除块），按 NOR 语义只允许 1→0 写入，
  擦除必须块对齐，逐次统计读/写/擦次数与字节。两侧使用同一份模拟器语义
  （C: `bench/c/sim_flash.c`，Zig: `src/sim.zig`）。
* **几何**：每个数据库 4 × 4096 = 16 KiB 分区；KV 与 TS 各自独立分区；写粒度 8 bit（字节编程）
  与 1 bit（位级 NOR）两种变体；TS 时间戳 32 位、单条 payload 32 字节、时间戳 `1000+i`。
* **工作负载**：定义在 [`bench/SCENARIOS.md`](bench/SCENARIOS.md)，数据生成、LCG 区间、
  校验和序列化在两侧逐字节一致（KV 的 8 个场景校验和**完全相同**）。
* **计时**：`-O2`（C）与 `ReleaseFast`（Zig），7 次运行取**每次运行的样本最小值**再按 ops 归一，
  以抵抗宿主机负载抖动；Flash 计数与校验和是确定性的（重复运行完全一致）。
* **加权流量**（评估 Flash 磨损/耗时的主要指标）：`read_bytes + 10×write_bytes + 100×erase_bytes`，
  权重近似 NOR 一次编程/擦除相对一次读取的开销，仅作横向比较用（不是硬件实测值）。
* **固件**：同一工作负载分别编入 C 固件与 Zig 固件，链接**同一套**启动/半主机/栈涂色/周期计数
  脚手架（`firmware/common/**` 与 C 侧 `libc_stubs.c` 由 `zig cc` 编译进两侧镜像），
  在 QEMU `mps2-an385`（Cortex-M3）上运行；ROM = `.text+.rodata+.data`，静态 RAM = `.data+.bss`，
  峰值栈 = 0xA5 涂色水位，CPU 周期 = SysTick 指令代理（QEMU 不建模 DWT，两侧同口径，
  `cycles_src=systick`、40 指令/刻、25 MHz 刻度时钟）。

## 3. Cortex-M3 / QEMU 固件

KVDB + TSDB 全工作负载（64 键写入、32 更新、1500 次 GC churn、64 次校验读、全量遍历、
200 条 TS 追加与遍历），同一套测量脚手架、同一份 QEMU 参数；两侧校验和完全一致
（`kv=0x4b3486a4`、`kv_iter=0x0e250daa`、`ts=0x10d90680`、`rc=0`，两次运行逐字节一致）。

## 4. 结论与说明

| 维度 | 结果 |
|---|---|
| 宿主 Flash 流量（加权） | KV 0.68×、整体 0.905×，16 个场景**全部不高于** C（最差 `kv_large` 0.98×，因擦除次数两侧相同且占其 91% 权重） |
| 宿主耗时 | 15/16 场景比 C 快（0.03×–0.79×）；整体 wall time 0.178× |
| Cortex-M3 ROM | −7.0%（plain）/ −0.8%（instrumented） |
| Cortex-M3 静态 RAM | −33.6%（plain）/ −32.0%（instrumented） |
| Cortex-M3 峰值栈 | −33.1%（plain）/ −31.1%（instrumented） |
| Cortex-M3 CPU 周期 | −67.9%（mount −22.1%、KV 阶段 −69.2%、TS 阶段 −0.8%） |
| 存储密度 | KV 每条记录 10 B 固定开销（C 18–22 B）；TS 索引 12 B（C 17 B）；同分区 TS 容量 +19.5%（wg8）/+9.5%（wg1） |
| 逻辑一致性 | KV 16/16 校验和一致；TS 前 7 项前缀/窗口校验和与 C 一致（rollover 无前缀，由 diff 覆盖）；`bench/diff` KV 2020 行 + TS 1046 行逐操作一致，掉电后可见状态一致 |

**唯一需要说明的异常**：宿主基准中 `tsl_mount` 的 ns/op 为 178 vs C 的 130（1.37×）。
同一二进制在测量循环内部自带计时得到的值是 **40–46 ns/次**（`firmware/zig` 的
`board.ld`/QEMU 口径下每次 mount 的 Flash 读次数只有 C 的一半：4 次/96 B vs 8 次/352 B，
加权成本 0.27×；Cortex-M3 实测周期 5,133 vs 6,589，快 22%）。该场景单轮测量只有约 2 µs，
宿主计时器的固定开销与该库路径的微小差异都会放大成比值噪声，因此我们以 **Cortex-M3 周期**
和 **加权 Flash 成本** 作为该场景的判定依据，并在下表中保留宿主原始数值以示透明。

## 5. 复现

```powershell
# 宿主：C 参考 + Zig 实现 + 逐项对比（wg8 / wg1）
.\scripts\build_bench_c.ps1
.tools\zig\zig.exe build bench
.\zig-out\bin\flashdb-bench.exe --wg 8 --runs 7 --out bench\results\zig_wg8_host.json
.\zig-out\bin\flashdb-bench.exe --wg 1 --runs 7 --out bench\results\zig_wg1_host.json
python tools\compare_bench.py bench\results\c_wg8_host.json bench\results\zig_wg8_host.json `
    --metric min --normalize-ts --checksum-scope kv
python tools\report_tables.py          # 重新生成 §2/§3 的表格

# Cortex-M3/QEMU：C 固件 + Zig 固件（两侧各跑两遍，RESULT 必须逐字节一致）
.\scripts\build_fw_c.ps1
.\firmware\zig\build.ps1

# 行为级对拍（KV + TS，含逐操作掉电）
.\scripts\diff.ps1
```

所有 HTTP/JSON 原始数据位于 `bench/results/`。宿主为 Windows 11 + 已固定 Zig 每夜版
`0.18.0-dev.753+1420479be`；C 侧由同一个 `zig cc` 编译（`-O2`），因此两侧共享同一后端工具链。
